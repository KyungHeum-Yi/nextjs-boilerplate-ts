# 게시글/댓글 기능 설계

## 목표

현재 인증이 적용된 Next.js 보일러플레이트에 네이버 카페와 유사한 기본 커뮤니티 흐름을 추가한다.

- 게시글 목록 조회
- 게시글 상세 조회
- 게시글 작성, 수정, 삭제
- 댓글 작성, 수정, 삭제
- 게시글과 댓글은 작성자 본인만 수정/삭제 가능

이번 범위는 게시판의 핵심 CRUD와 권한 제어에 집중한다. 카테고리, 대댓글, 좋아요, 첨부파일, 검색, 정렬 옵션 확장은 이번 범위에 포함하지 않는다.

## 구현 방향

이번 기능은 App Router와 서버 액션 중심으로 구현한다.

- 읽기 화면은 서버 컴포넌트에서 Prisma로 직접 조회
- 쓰기 동작은 서버 액션으로 처리
- 권한 검사는 서버 액션 내부에서 수행
- UI는 현재 프로젝트의 shadcn/ui 스타일과 단순한 레이아웃을 유지

이 방식을 선택한 이유는 현재 프로젝트가 인증과 서버 렌더링 중심 구조를 이미 가지고 있고, 작성자 권한 검사를 서버 액션 안에서 가장 간단하고 안전하게 처리할 수 있기 때문이다.

## 데이터 모델

기존 `User` 모델에 게시글과 댓글 관계를 추가하고, 새 모델 `Post`, `Comment`를 도입한다.

### Post

- `id`: 문자열 기본 키
- `title`: 게시글 제목
- `content`: 게시글 본문
- `authorId`: 작성자 `User.id`
- `createdAt`: 생성 시각
- `updatedAt`: 수정 시각

### Comment

- `id`: 문자열 기본 키
- `content`: 댓글 본문
- `postId`: 대상 게시글 `Post.id`
- `authorId`: 작성자 `User.id`
- `createdAt`: 생성 시각
- `updatedAt`: 수정 시각

### 관계

- 한 명의 사용자는 여러 개의 게시글을 작성할 수 있다.
- 한 명의 사용자는 여러 개의 댓글을 작성할 수 있다.
- 한 개의 게시글은 여러 개의 댓글을 가질 수 있다.
- 게시글이 삭제되면 연결된 댓글도 함께 삭제된다.

## 권한 규칙

권한 규칙은 서버에서 강제한다.

- 로그인한 사용자만 게시글 작성 가능
- 로그인한 사용자만 댓글 작성 가능
- 게시글 수정/삭제는 해당 게시글 작성자만 가능
- 댓글 수정/삭제는 해당 댓글 작성자만 가능
- 권한이 없는 사용자는 수정/삭제 버튼을 UI에서 보지 못하게 한다.
- UI를 우회해 서버 액션을 직접 호출하더라도, 서버에서 다시 작성자 여부를 검사해 차단한다.

현재 세션에서 신뢰할 값은 로그인 사용자 식별자뿐이며, 실제 권한 판단은 반드시 DB의 `authorId`와 비교한다.

## 라우팅 구조

### `/`

- 게시글 목록 페이지
- 최신 게시글 목록 표시
- 로그인 상태면 `글쓰기` 버튼 표시
- 비로그인 상태면 목록은 볼 수 있지만 쓰기 버튼은 숨김

### `/posts/new`

- 게시글 작성 페이지
- 제목과 본문 입력 폼 제공
- 로그인 사용자만 접근 가능

### `/posts/[postId]`

- 게시글 상세 페이지
- 게시글 제목, 본문, 작성자, 작성일 표시
- 본인 글인 경우 수정/삭제 버튼 표시
- 댓글 목록 표시
- 로그인 상태면 댓글 작성 폼 표시
- 본인 댓글인 경우 해당 댓글에 수정/삭제 버튼 표시

### `/posts/[postId]/edit`

- 게시글 수정 페이지
- 작성자 본인만 접근 가능
- 기존 제목/본문을 불러와 수정 가능

댓글 수정은 별도 페이지를 만들지 않고 게시글 상세 화면 안에서 인라인 수정 폼으로 처리한다.

## 서버 액션 설계

### 게시글 관련

- `createPost`
  - 입력: 제목, 본문
  - 처리: 로그인 사용자 확인 후 게시글 생성
  - 결과: 생성된 게시글 상세 페이지 또는 목록으로 이동

- `updatePost`
  - 입력: 게시글 id, 제목, 본문
  - 처리: 게시글 조회 후 작성자 본인인지 확인하고 수정
  - 결과: 상세 페이지로 이동

- `deletePost`
  - 입력: 게시글 id
  - 처리: 게시글 조회 후 작성자 본인인지 확인하고 삭제
  - 결과: 목록 페이지로 이동

### 댓글 관련

- `createComment`
  - 입력: 게시글 id, 댓글 내용
  - 처리: 로그인 사용자 확인 후 댓글 생성
  - 결과: 상세 페이지로 새로고침 또는 재검증

- `updateComment`
  - 입력: 댓글 id, 댓글 내용
  - 처리: 댓글 조회 후 작성자 본인인지 확인하고 수정
  - 결과: 상세 페이지 재검증

- `deleteComment`
  - 입력: 댓글 id
  - 처리: 댓글 조회 후 작성자 본인인지 확인하고 삭제
  - 결과: 상세 페이지 재검증

## 데이터 조회 방식

### 게시글 목록

- 최신순 정렬
- 작성자 이름 또는 이메일 일부 표시
- 게시글 제목과 작성일 표시

### 게시글 상세

- 게시글 1건 조회
- 작성자 정보 포함
- 댓글 목록 함께 조회
- 댓글도 생성일 기준 정렬

초기 버전에서는 페이지네이션 없이 단순 목록으로 시작한다. 데이터가 늘어나면 추후 페이지네이션을 추가한다.

## UI 구성

현재 프로젝트의 미니멀 스타일을 유지하되, 게시판 형태가 드러나도록 구성한다.

- 목록은 카드형 리스트 또는 간단한 섹션 리스트
- 상세 화면은 본문 카드 + 댓글 섹션
- 작성/수정 폼은 제목 input, 본문 textarea, 저장/취소 버튼
- 댓글은 본문, 작성자, 작성 시간, 수정/삭제 액션 표시

UI는 기능 이해와 권한 차이를 분명히 보여주는 데 집중한다. 화려한 상호작용보다 명확한 상태 표현이 우선이다.

## 에러 처리

- 비로그인 상태에서 글/댓글 작성 시도: 로그인 필요 안내 또는 로그인 페이지 유도
- 권한 없는 수정/삭제 시도: 서버 액션에서 거절
- 존재하지 않는 게시글 접근: 404 처리
- 존재하지 않는 댓글 수정/삭제 시도: 안전하게 실패 처리
- 제목/본문/댓글 내용이 비어 있으면 제출 거절

## 파일 구조 제안

- `prisma/schema.prisma`
  - `Post`, `Comment` 모델 추가
  - `User` 관계 필드 추가

- `lib/actions/post-actions.ts`
  - 게시글 서버 액션

- `lib/actions/comment-actions.ts`
  - 댓글 서버 액션

- `app/page.tsx`
  - 게시글 목록으로 개편

- `app/posts/new/page.tsx`
  - 게시글 작성 페이지

- `app/posts/[postId]/page.tsx`
  - 게시글 상세 페이지

- `app/posts/[postId]/edit/page.tsx`
  - 게시글 수정 페이지

- 필요 시 `components/board/` 하위
  - 게시글 폼
  - 댓글 폼
  - 댓글 리스트

## 검증 계획

수동 검증 기준은 아래와 같다.

1. 로그인 사용자가 게시글을 작성할 수 있다.
2. 작성한 게시글이 목록과 상세에 정상 표시된다.
3. 작성자 본인은 게시글 수정/삭제 버튼을 볼 수 있고 동작한다.
4. 다른 사용자는 해당 게시글 수정/삭제 버튼을 볼 수 없다.
5. 로그인 사용자가 댓글을 작성할 수 있다.
6. 작성자 본인은 댓글 수정/삭제가 가능하다.
7. 다른 사용자는 해당 댓글 수정/삭제 버튼을 볼 수 없다.
8. 서버 액션 차원에서도 권한 없는 수정/삭제 요청이 거절된다.
9. 게시글 삭제 시 연결된 댓글도 함께 정리된다.

## 범위 제외

이번 설계에는 아래 항목을 포함하지 않는다.

- 카테고리/게시판 분류
- 대댓글
- 좋아요/추천
- 검색
- 페이지네이션
- 첨부파일 업로드
- 관리자 권한

이 항목들은 게시판 핵심 흐름이 안정화된 뒤 별도 단계로 확장한다.
